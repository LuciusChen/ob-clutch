#+title: ob-clutch

Org-Babel integration for the [[https://github.com/LuciusChen/clutch][clutch]] database client.

* Installation

=ob-clutch= requires Emacs 29.1 or later and depends on the =clutch= package, version 0.5.2 or later:

#+begin_src emacs-lisp
(use-package clutch)
(use-package ob-clutch
  :after clutch)
#+end_src

Native MySQL and PostgreSQL additionally require the optional =mysql= and =pgsql= protocol packages. Clutch loads each package when that backend connects; SQLite uses Emacs's built-in SQLite support.

Generic JDBC blocks require [[https://github.com/LuciusChen/clutch][clutch]]'s JDBC bridge as well:

#+begin_src emacs-lisp
(require 'clutch-db-jdbc)
#+end_src

* Supported block types

- =mysql=
- =postgresql=
- =sqlite=
- =clutch= (generic entry point)

Generic =clutch= blocks can target JDBC backends such as Oracle or SQL Server
with a =:backend= header argument.

* Saved connections and passwords

=:connection= resolves entries from =clutch-connection-alist= through Clutch's public saved-connection API. A saved =:backend= wins over the block language; without it, language-specific blocks use their backend and generic =clutch= blocks use =mysql=. Inline and saved backend names use Clutch's alias registry.

Password resolution follows clutch's connection rules:

1. =:password=
2. A saved =:profile-entry= supplies its profile secret unless an explicit =:password= or =:pass-entry= overrides it.
3. =:pass-entry= via =auth-source-pass=
4. =auth-source-search= via =:host= / =:user= / =:port=

When a saved connection has no =:password=, =:pass-entry=, or =:profile-entry=, Clutch defaults =:pass-entry= to the connection name so pass entries like =mysql/dev= can still match =dev=. Babel does not inject a second password source beside a profile or modify the saved entry.

Saved connections and inline headers also honor Clutch transport keys:
=:ssh-host=, =:tramp=, and the longer =:tramp-default-directory= spelling.
When a block is executed from a TRAMP org buffer and no explicit transport is
configured, =ob-clutch= applies =clutch-tramp-context-policy= before connecting.

* Header arguments

- =:connection=
- =:backend=
- =:host=
- =:port=
- =:user=
- =:password=
- =:database=
- =:pass-entry=
- =:ssh-host=
- =:tramp=
- =:max-rows=
- =:async=

Backend-specific headers are passed through when relevant:

- PostgreSQL: =:schema=, =:tls=, =:sslmode=, =:query-timeout=
- MySQL: =:tls=, =:ssl-mode=
- JDBC: =:url=, =:driver-class=, =:sid=, =:catalog=, =:manual-commit=, =:rpc-timeout=

Generic =:backend jdbc= blocks require an explicit =:driver-class=, for example =:url jdbc:h2:mem:demo :driver-class org.h2.Driver :user sa=. The corresponding driver jar must be installed in Clutch's JDBC runtime.

=:max-rows= limits the data rows a block returns.  The default is 1000, set by
=ob-clutch-max-rows=; a few tens of thousands of rows already make Emacs
unresponsive while Org inserts the table.  For a =SELECT= without a row limit
of its own, ob-clutch asks the server for one row more than the limit, so a
large table is not fetched in full.  When more rows exist, the table ends with
a line below a rule, =First N rows shown, more follow=; that line is part of the
table, so use =:max-rows nil= or a larger limit when another block reads the
result.  Use =:max-rows nil= to send the SQL as written and return every row.

* Asynchronous blocks

=:async yes= runs the statement without blocking Emacs, on native MySQL and PostgreSQL and on JDBC connections:

#+begin_src org
,#+begin_src postgresql :connection prod :async yes
SELECT pg_sleep(30), count(*) FROM orders;
,#+end_src
#+end_src

The block shows =Running ob-clutch-N= under =#+RESULTS:= and gets its table, or =Error: ...=, when the statement ends.  A connection refuses other work while a statement runs, so blocks that use the same connection wait for each other and run one after another, shown as =Queued ob-clutch-N=; blocks on different connections run together.  Running a block again while its earlier run is unfinished does not cancel the earlier statement, but only the latest run writes the result.  A result you edited or deleted meanwhile is left alone.  Backends that cannot run SQL without blocking Emacs, such as SQLite, run the block at once and return its result as usual.

=M-x ob-clutch-cancel-block-at-point= cancels the run of the block at point.  A queued block is dropped and shows =Cancelled=.  A running statement is interrupted, and the block shows the server's answer: the cancellation error, or the result if the statement had already finished.  A synchronous block on a connection that an asynchronous one is using fails with the connection's busy error; make it asynchronous too, so that it queues.

* Examples

MySQL:

#+begin_src org
#+begin_src mysql :connection dev
SELECT 1;
#+end_src
#+end_src

PostgreSQL:

#+begin_src org
#+begin_src postgresql :host 127.0.0.1 :port 5432 :user postgres :database app :schema public :max-rows 20
SELECT now();
#+end_src
#+end_src

SQLite:

Relative =:database= filenames are resolved by Clutch against the block's local execution directory before caching. Different directories' =app.db= files do not share a connection; equivalent relative and absolute paths to the same file reuse one connection. =:memory:= keeps its existing cached in-memory behavior. This needs Clutch 0.5.1 or later.

#+begin_src org
#+begin_src sqlite :database /tmp/demo.db
SELECT sqlite_version();
#+end_src
#+end_src

Generic clutch/JDBC:

#+begin_src org
#+begin_src clutch :backend oracle :connection prod-oracle
SELECT sysdate FROM dual
#+end_src
#+end_src

Inline JDBC:

#+begin_src org
#+begin_src clutch :backend oracle :host db.example.com :port 1521 :user scott :sid ORCL
SELECT sysdate FROM dual
#+end_src
#+end_src
